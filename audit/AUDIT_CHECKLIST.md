# 审计清单与结论

## 复核步骤

- [x] **数据来源**：随包数据仅为合成 CSV；README、界面和报告均声明公开/合成数据边界。
- [x] **输入校验**：必填字段、日期、非空渠道、数值、非负值、`orders <= sessions` 和期间级漏斗分母均有代码约束与测试。
- [x] **计算可追溯性**：KPI 公式、预警阈值与收入顺序分解均已文档化；`revenue_impact` 可机器读取。
- [x] **归因一致性**：测试逐期验证会话量、转化率、客单价三项收入影响之和等于实际收入变化。
- [x] **建议边界**：建议由结构化证据触发，并在 UI 与 Markdown 报告中要求业务复核。
- [x] **LLM 最小化**：默认关闭；仅发送确定性输出；拒绝数值型 LLM 返回，避免新增指标。
- [x] **接口表面**：健康检查、正常分析和无效输入响应均由 FastAPI 测试覆盖。
- [x] **基础完整性**：通过单元/接口/工作流测试、Python 编译检查和 wheel 构建；详见 [验证记录](VERIFICATION.md)。

## 本次关闭的发现

| 编号 | 风险 | 处理 |
|---|---|---|
| AUD-01 | 某个期间的整体订单或收入为零时，转化率或客单价没有定义，可能让后续归因失败。 | 在 `validate_dataframe` 中拒绝该期间，并新增回归测试。 |
| AUD-02 | 收入影响只存在于自然语言解释中，不利于独立复算。 | 在证据记录中新增 `revenue_impact`，并逐期测试其与收入变化的恒等关系。 |
| AUD-03 | 根目录存在未被引用、与包模块相同的 `llm_summary.py`，会造成审阅歧义。 | 已移除重复副本，保留唯一的 `business_analysis_agent/llm_summary.py`。 |

## 剩余限制与建议

| 优先级 | 限制 | 审阅建议 |
|---|---|---|
| P2 | 依赖在 `pyproject.toml` 中是版本区间，尚无锁定文件。 | 生产或正式交付前在受控 Python 环境生成锁文件，并将其纳入发布审计。 |
| P2 | 归档时源目录尚无 Git 提交。 | 由项目所有者审阅本包后创建初始提交、签署版本标签并保存构建日志。 |
| P2 | 本次未对外部 LLM、Docker 镜像或生产部署做运行验证。 | 如启用这些能力，应单独进行密钥、网络、镜像、权限和日志审计。 |
| P3 | 预警阈值是示例规则，不含组织特定的季节性或预算口径。 | 在真实数据接入前由业务负责人建立指标字典和阈值审批记录。 |

## 审计结论

对于“公开合成数据、单用户本地演示、确定性经营诊断”的声明范围，本包具备可读的输入契约、可复算的核心公式和基础自动化验证。它尚不应被描述为已通过真实业务、生产安全或外部模型集成审计。
